# Bilingual UI and Error Presentation

## 1. Scope / Trigger

- Read this contract when adding user-visible text, language-aware formatting, settings rows, retained feedback, parser failures or native error/event fields.
- Keep backend error construction in [Error Handling](../backend/error-handling.md). Keep preference lifecycle and six-section navigation in [Settings and Clipboard](./settings-clipboard.md).

## 3. Contracts

### Locale ownership and startup

- Persist only the preference string under localStorage key `locale`. Keep it outside `adb-gui-settings`, theme storage and `adb-gui-ui`. Do not persist catalogs or resolved runtime state.
- Initialize the locale store synchronously before the first React render. Set `document.documentElement.lang` to the resolved locale when initializing or changing it.
- In system mode, inspect the first nonempty system language only. A case-insensitive primary subtag `zh` resolves to `zh-CN`; every other language and an empty list resolve to `en`. Do not search lower-priority languages for Chinese. `navigator.languages` takes precedence over `navigator.language`, including an explicitly empty list.
- Accept only `system`, `zh-CN` and `en` as stored preferences. Repair an invalid non-null value to `system` on a best-effort write. Missing/unreadable storage uses system mode. A failed write must not disable the language control or prevent an in-memory choice from taking effect; persistence is not guaranteed in that condition.
- React to `languagechange` only in system mode. Dispose the browser listener for HMR/tests. An explicit language remains effective until the user changes it.
- Render the language row first in General, outside the disabled settings fieldset. Include `localePreference` in modified-row snapshots, but preserve it during both section reset and global reset. Use `hasSectionResetChanges` for reset-button visibility so a language-only modification does not expose a no-op reset.

### Native Settings menu

- Keep the locale store independent of the Tauri bridge. Start native synchronization in `src/main.tsx` after module initialization; emit the current resolved locale once, then emit only when the resolved locale changes. Unsubscribe on HMR.
- On macOS, create the Settings menu item in `src-tauri/src/menu_locale.rs` using `sys-locale 0.3.2` and the same first-nonempty-language rule. Register its `locale-changed` listener while building the menu, before the WebView can emit.
- Send only `"zh-CN"` or `"en"` as the JSON string event payload. Reject `system`, regional aliases and malformed payloads with diagnostics; leave the existing menu title intact. Report menu-update failures without changing frontend locale state.
- Allow the native Settings title to use the system language before the WebView initializes. The first frontend event applies the user's saved override. Do not attempt to read WebView localStorage in Rust or introduce a second persistent preference.
- Preserve menu ID, `Cmd+,`, `open-settings` behavior and macOS-only registration. This synchronization owns the custom Settings item, not platform-managed standard menu behavior.

### Catalogs and render-time text

- Aggregate locale modules in `messages/zh-CN.ts` and `messages/en.ts`, then expose both through the single `messages/index.ts` catalog table. Keep `backend-*`, `tools-*` and `streams-*` catalogs split by responsibility without independent runtime locale selection.
- Infer the text shape from the Chinese catalog and type the English catalog as `Messages`. Do not add `as const` to the base text catalog: strings must widen rather than constrain English values to Chinese literals.
- Define error-code parameter schemas in `errorContract.ts` and its module contracts; keep translated error functions in locale catalog files. Add each backend code to `src-tauri/src/error_codes.rs`, `backendErrorContract.ts` and both backend error catalogs together.
- Use `useT()` in every component that presents translated text, including components which call a helper with a dynamic label getter. Use `messages()` for non-React, click-time bridge work; never evaluate it at module load to freeze a translated label.
- Reuse `common` short actions. Put a complete sentence in one named function entry with semantic parameters such as `count`, `path` or `detail`. Handle English pluralization in that entry. Do not concatenate a translated prefix, a number and a translated suffix in JSX.
- Keep paths, application names, package names, log records, decoded data and raw external diagnostics unchanged. Distinguish synthetic source names from data: decoded clipboard images retain `sourceKind: "clipboard"` and derive their display name at render time.
- `SettingsRowMeta.label`, optional `description` and section labels are `(messages: Messages) => string`. Resolve option-label functions using the current catalog without changing enum values or validation.
- `LOGCAT_COLUMNS` deliberately retains stable `column` metadata and `label` getters which call `messages()`. Consumers must subscribe with `useT()` and read the getter during rendering; do not destructure its labels into module-level constants or permanently cached arrays.

### Retained feedback and errors

- Keep `ToastMessage = Message | AppErrorPayload`. Pass toast product text as a `Message` callback, and failure data as an `AppErrorPayload`. The callback receives the render's current catalog; do not capture a previously evaluated string or an outer `t` inside a zero-argument callback.
- Store `AppErrorPayload` until rendering in settings errors, generator input errors, decoded batches, file list/preview/transfer errors, recording state and stream failures. Use `toAppError` at unknown/plugin boundaries. Preserve nested application failures in `causes`; reserve `detail` for raw diagnostics.
- Render failures with `errorText(payload, t)` or `translateError(payload, t)`. Do not stringify an error payload or translate it before placing it in a store. Changing language must not rerun decoding/generation, restart streams or reset retained results.
- Keep query failure ranges with their payload. Compare stable error content and `start/end`, not translated wording. Translate the position and error in `LogcatQueryInput`; preserve the last valid query/AST when a draft fails.
- Deduplicate repeated operational failures with `errorIdentity(value)`, which normalizes the payload and recursively sorts object keys before serialization. Preserve cause-array order; distinguish changes in code, parameters, raw detail or causes. Never compare `String(payload)` (`[object Object]`) or translated messages to decide whether to suppress feedback.
- Preserve `logcat-exit` and `device-metrics-exit` identifiers and `reason: "error" | "eof"` markers. Their `detail` field carries `AppErrorPayload | null`, not preformatted prose. Native EOF without stderr still supplies a coded error (`logcat.eof` or `metrics.eof`). Keep backend diagnostics and nested causes available after translation.
- Treat `DeviceDetail.battery_status` as presentation-independent data. Map Android status `2/3/4/5` to `charging/discharging/not_charging/full`; map other parsed values to `unknown`. Translate recognized codes through `batteryStatusLabel`; preserve an unknown external string or absent empty value rather than translating it as a device name.
- Preserve the four historical Chinese battery labels in exported Bugreport `info.txt`; that non-UI file format is separate from `DeviceDetail`. Do not use exported report text as a UI status source or expand this exception to other application prose.

### Formatting and memo dependencies

- Reuse the per-locale Intl caches in `i18n/format.ts`. Performance times deliberately remain 24-hour in both languages (`hour12: false`).
- Keep `appInfo.ts` and `deviceFiles.ts` free of locale-store imports. Pass `Intl.Collator`, `Locale` or `Messages` into pure display helpers. Preserve raw arrays and stable selection keys when sorting.
- Call `sortAppInfo(apps, preferences, appNameCollator(locale))` from a memo whose dependencies include `locale`. A `useT()` rerender alone does not recompute an unchanged memo. Apply the same dependency rule to chart labels and formatted view projections.
- Do not describe English Intl collation as guaranteed Unicode code-point order. Assert the selected locale's order on fixed mixed-language samples, including natural numeric name order.

## 4. Validation & Error Matrix

| Input/state | Required result |
| --- | --- |
| System languages `["en-US", "zh-CN"]` | English; do not prefer the second entry |
| Invalid stored preference or unavailable browser language APIs | System preference; declared non-Chinese fallback when resolution has no language |
| Locale differs only because General language was changed | Modified language row remains visible; section/global reset preserve locale |
| Existing toast/query/generator/recording failure during language switch | Rerender its message using the same stored data; no action retry or stream restart |
| Known error code with missing/wrong parameter types | Render `invalid_payload`; never interpolate `undefined` |
| Unknown error code or bare plugin error | Keep unknown code/raw detail diagnosable under the localized generic failure |
| Malformed/cyclic payload, non-finite numeric parameter | Reject at `toAppError`; recursive input is bounded to depth 8 and 16 causes per node |
| Native exit without stderr | Retain EOF reason plus a nonempty coded payload |
| English app sort | Recompute with English collator while preserving package selection and device text |

## 5. Good/Base/Bad Cases

- Good: store `generator_empty_input`, then display its Chinese or English error without calling `generate()` again.
- Base: read translated native dialog labels just before opening; its captured labels determine that already-open dialog's response.
- Bad: store `showToast("success", t.common.copied)` or memoize application sorting without the locale dependency.
- Bad: translate a backend failure in Rust, or flatten nested cleanup/session errors with `format!("{error}")` before crossing IPC.

## 6. Tests Required

- Run `src/i18n/catalog.test.ts` to enforce identical catalog shape and the AST CJK guard. Its only native-language-name exception is the exact `chinese: "简体中文"` property in `messages/en.ts`; Chinese catalogs (`zh-CN.ts` and `*-zh-CN.ts`) and `.test.ts`/`.test.tsx` files are outside the guard. Do not broaden this to a blanket English-catalog or fixture-directory exception.
- Cover locale initialization, explicit overrides, first-language priority, invalid/unavailable storage, `languagechange` and listener cleanup in the locale tests. Rust menu tests must reject unresolved/invalid event values.
- Cover error-schema parity, numeric/string parameters, nested causes, malformed inputs and unknown codes. Native serialization tests must retain numeric types and omit empty optional fields.
- Cover `errorIdentity` equality across object-key order and inequality when code, parameters, detail or cause order changes. Verify repeated polling failures stay suppressed while a materially different failure is shown.
- Exercise retained-state switching with `ToolLocalization.test.tsx`, `streams-i18n.test.tsx` and controller/store regressions. Assert preserved batch/query/session identity and no repeated action, not only English dictionary contents.
- Lock mixed-language application ordering and both file date layouts in pure-helper tests. Keep real source names/data unchanged.
- Browser-check both themes at 1200x800 and 900x600, language changes with existing errors, six settings sections, long English labels and menus. Record native/device validation separately; SSR or a browser bridge mock does not verify a macOS menu or Android command.

## 7. Wrong vs Correct

```tsx
// Wrong: the stored callback closes over an already translated string.
const text = t.common.copied;
showToast("success", () => text);

// Correct: resolve text against the catalog supplied at rendering.
showToast("success", (current) => current.common.copied);

// Wrong: a memo ignores the language even though the component rerenders.
const apps = useMemo(() => sortAppInfo(source, preferences, appNameCollator(locale)), [source, preferences]);

// Correct: locale controls ordering without restarting the loading effect.
const apps = useMemo(() => sortAppInfo(source, preferences, appNameCollator(locale)), [source, preferences, locale]);
```
