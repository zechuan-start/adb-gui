# 界面中英双语与语言设置

## 产品与目标

ADB GUI 是一个 Android 开发测试桌面工具 app. 本任务让它的界面在简体中文和英文之间完整可切换, 并在首次启动时按系统语言自动选择: 系统语言是中文就用中文, 其余一律用英文.

这不是一次"加个语言下拉框"的改动. 当前 810 行前端文案和 181 行后端错误文案全部硬编码中文, 英文用户实际拿到的是一个中文软件. 目标是让英文用户从启动第一屏到任何一条错误提示都读到英文, 且不需要任何配置.

这不是什么:

- 不是多语言平台. 只做 `zh-CN` 和 `en` 两种, 不引入语言包插件化, 不做运行时下载词典.
- 不是内容翻译. 设备返回的包名, 日志正文, 文件名, adb 原始输出保持原样, 不翻译.
- 不是排版重构. 不为英文重做布局体系, 只修复英文变长后确实被截断或溢出的具体位置.

## 已确认

- 2026-09-08 用户要求做中英双语, 并在设置中提供语言项, 默认跟随系统, 非中文回落英文.
- 用户选定自研轻量 typed catalog, 不引入 react-i18next 或其他 i18n 依赖.
- 用户选定后端错误码化: Rust 返回结构化错误码与参数, 文案落在前端词典.
- 用户选定父任务 + 子任务拆分, 不做成一个巨型任务.

## 待确认

- 应用名排序的 collator 语言. 英文界面下, 中文应用名用英文 collator 排序会从拼音序变成码点序. 推荐做法: collator 跟随界面语言, 保持"界面语言决定一切呈现"的一致规则, 在 `i18n-tool-pages` 验收时用真实设备确认可接受. 若不可接受, 退路是 collator 固定 `zh-CN`, 只有数字与日期跟随界面语言.

## 语言解析规则 (P0 核心)

存储三态: `system` (默认) / `zh-CN` / `en`. 解析出的生效语言只有两种: `zh-CN` 或 `en`.

- 偏好为 `zh-CN` 或 `en`: 直接生效, 不看系统.
- 偏好为 `system`: 按顺序扫描系统语言列表, 取第一条语言标签的主子标签. 主子标签是 `zh` 就用 `zh-CN`, 否则用 `en`.
- `zh-TW`, `zh-Hant`, `zh-HK` 一律解析为 `zh-CN`. 本任务只出简体, 不做繁体分支, 也不因为拿不到繁体词典就回落英文.
- 系统语言列表为空或不可读: 用 `en`. 这是"不是中文就用英文"规则的直接结果.
- 偏好为 `system` 时, 系统语言在运行中改变要立即生效, 不要求重启.

## P0 范围

| 分组 | 能力 | 为什么是 P0 |
| --- | --- | --- |
| 语言设置 | 设置面板"通用"分组新增语言行, 三档: 跟随系统 / 简体中文 / English | 没有这一行, 用户无法覆盖系统判断, 双语只是半个功能 |
| 首启行为 | 未设置过语言时按系统语言选定, 非中文用英文 | 用户明确要求的默认行为, 也是英文用户唯一能读懂界面的路径 |
| 即时切换 | 切换语言后当前界面立即变化, 不重启, 不丢当前设备/日志/输入 | 工具型 app 的语言切换若要求重启, 会打断正在进行的抓日志或录屏 |
| 前端文案 | 外壳, 设置面板, 六个工作区的全部可见文案与 aria-label 走词典 | 漏一处就是英文界面里的一块中文, 双语可信度归零 |
| 后端文案 | Rust 命令改为返回错误码与参数, 由前端词典翻译 | 失败提示是英文用户最需要读懂的一类文案, 留中文等于没做 |
| 本地化格式 | 数字, 日期, 时间, 应用名排序跟随生效语言 | 现有 4 处硬编码 `zh-CN` 会让英文界面出现中式日期, 属于同一功能的完整性 |
| 防回归 | 测试断言改为引用词典, 并加一条禁止新增硬编码中文的守卫测试 | 810 行一次性迁完之后, 没有守卫就会在下一个功能里重新长出中文字面量 |

## P1 / P2 / 不做

- P1: 繁体中文词典, 日文等第三语言, 英文长文案的布局微调专项, 语言偏好随设置导出.
- P2: 词典按工作区懒加载, 界面语言与内容排序语言分开配置, 词条覆盖率的 CI 报表.
- 不做: 翻译设备返回值 (包名, 日志正文, adb 输出, 文件名), 翻译第三方插件自带的系统对话框按钮 (由 OS 提供), 重排布局体系, 改动 `productName` 与窗口标题 (品牌名保持 `ADB GUI`).

## 共同要求

- 语言偏好独立于 `adb-gui-settings` 存储. 设置文件损坏时读取失败的提示本身也要按正确语言显示, 所以两者不能互相依赖.
- 词典以 `zh-CN` 为基准, 英文词典由类型约束成同构. 缺 key, 多 key, 参数类型不符一律编译期失败, 不允许运行时静默回落到 key 名或另一种语言.
- 设备无连接时语言可正常切换, 不触发任何 adb 调用.
- 破坏性操作 (放弃未保存录屏, 恢复默认设置, 卸载应用, 清数据) 的确认文案必须双语齐备, 且英文确认按钮语义不弱于中文, 不允许英文缺失导致直接执行.
- 语言切换不改变任何已保存的用户内容: 不重命名已保存截图/录屏文件, 不改写设置值, 不清空日志缓冲或生码结果.
- 恢复默认设置不重置语言偏好. 语言是与主题同级的外壳偏好, 不属于任何设置分组的 reset 计划.

## 跨任务验收

- [ ] 全新环境 (清空 localStorage) 下, 系统语言为中文时首屏中文; 系统语言为英文/法文/日文时首屏英文.
- [ ] 系统语言 `zh-TW` 时首屏为简体中文, 不是英文.
- [ ] 设置里选定语言后, 系统语言再变化不影响界面; 改回"跟随系统"后立即重新按系统语言解析.
- [ ] 切换语言即时生效, 且当前选中设备, 日志滚动位置, 生码输入与结果, 录屏进行状态均不丢失.
- [ ] 英文界面下遍历六个工作区与设置七个分组, 无残留中文 (设备返回值除外).
- [ ] 英文界面下触发失败路径 (设备离线上传文件, 无权限目录, 录屏保存失败, 设置文件损坏), 提示为英文且含可诊断细节.
- [ ] 英文界面下数字千分位, 日期与时间格式为英文习惯; 中文界面维持现状不变.
- [ ] 原生菜单 "设置…" / "Settings…" 跟随语言.
- [ ] 破坏性操作确认弹窗在两种语言下按钮与说明齐备.
- [ ] `pnpm test` 与 `pnpm build` 通过; 守卫测试能拦住新增的硬编码中文.
- [ ] 双尺寸 (1400x880 与最小宽度) 与双主题下, 英文长文案无截断或横向溢出.
- [ ] macOS 真机构建冒烟: 首启语言判断, 语言切换, 一条真实失败提示.
