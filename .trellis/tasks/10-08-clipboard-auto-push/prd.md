## 产品形态

桌面工具型 app 里的一个可选开关. 打开后, 用户在电脑任意应用里新复制的文本, 会自动写入当前选中手机的剪贴板, 省去切回本应用点 "推送到手机".

它不是:

- 双向同步. 手机 -> 电脑仍然只有手动按钮.
- 常驻系统的后台服务. 只在本应用运行时工作, 退出即停止.
- 剪贴板历史或预览工具. 不显示, 不保存, 不记录剪贴板内容.

## 用户工作流

1. 在工具页剪贴板模块 (A-09) 或 设置 > 通用 打开 "自动推送到手机".
2. 切到浏览器, 编辑器等其他应用复制一段文本.
3. 不切回本应用, 直接在手机上粘贴.
4. 回到本应用时, 剪贴板模块显示最近一次推送的结果 (成功时间, 或锁屏等失败原因).

## 已确认事实

- 现在只有两个手动方向按钮, 每次点击执行一次传输 (`src/components/ClipboardTool.tsx`, `src/lib/clipboardTransfer.ts`).
- 写入手机走 `set_device_clipboard`: 每次都要执行一次 `adb shell` + `app_process` 启动 DEX 辅助程序, 有几百毫秒开销 (`src-tauri/src/commands/clipboard.rs`).
- 辅助程序只支持主用户, 解锁状态; 锁屏时返回 `clipboard.locked`.
- 文本上限 256 KiB; 写入以回读一致为准, 已提交的写入不自动重试 (`.trellis/spec/backend/clipboard.md`).
- `@tauri-apps/plugin-clipboard-manager` 没有内容变化事件.
- macOS `NSPasteboard.changeCount` 和 Windows `GetClipboardSequenceNumber` 是剪贴板变化计数, 查询不读取内容, 开销可忽略. Linux 没有等价的低成本计数.
- 发布目标包含 macOS, Windows, Linux (`.github/workflows/release.yml`).
- 现有规范 `settings-clipboard.md` 规定剪贴板 "只在点击时读取, 不轮询", 本功能需要修订这条契约.
- 设置新增字段缺省时取默认值, 不需要提升 `SETTINGS_VERSION` (同 `performance.backgroundEnabled` 的做法).

## 推测与风险

- Android 13+ 每次剪贴板被写入可能弹出系统预览浮层, 自动推送时每次复制都会在手机上出现一次.
- macOS 在 15.4 起预览了 "程序读取剪贴板时弹隐私提示" (`EnablePasteboardPrivacyDeveloperPreview`), 26 默认未启用, 27 是否启用未验证. 若启用, 自动读取剪贴板会触发系统提示, 用户可选择始终允许.
- 本应用窗口被遮挡或最小化时, WebKit 可能节流或挂起网页任务. 因此推送链路放在 Rust, 不依赖网页计时器.

## 已确认决策 (2026-10-19)

| 问题 | 决策 |
| --- | --- |
| 开关是否持久化 | 持久化到设置, 默认关闭. 模块开关和 设置 > 通用 一行写同一个设置项. |
| 敏感内容保护 | 不做额外保护. 开关打开即推送所有新复制的文本, 只保留现有 256 KiB 上限. 用户知情: 密码管理器复制的密码也会被推送. |
| Linux | P0 不支持. Linux 上开关禁用并说明暂不支持. |
| 状态展示 | 只在剪贴板模块内显示一行状态. 自动推送的成功和失败都不弹 toast. |
| 检测频率 | 每 500 ms 查询一次变化计数, 计数变化才读取文本. 应用失去焦点不暂停. |
| 已有内容 | 打开开关, 切换设备或设备重新上线时, 不推送剪贴板里已有的内容, 只推送之后新复制的. |

## P0 范围

- 设置项 `clipboard.autoPush` (默认 `false`), 剪贴板模块内开关 + 设置 > 通用 一行, 两处写同一个 store action. 原因: 持久化开关是功能可用的前提.
- 开关打开, 设置可用, 选中设备在线时启动自动推送; 任一条件不满足即停止. 原因: 不能在用户未授权或无目标设备时读取电脑剪贴板.
- 电脑剪贴板变化后读取文本, 推送到当前选中设备. 原因: 核心价值.
- 与上次成功推送到同一设备的内容相同则不推送. 原因: 验收要求 "重复复制同一内容不重复推送".
- 推送进行中不排队, 推送结束后只处理最新的剪贴板内容. 原因: 连续复制时避免堆积进程.
- 失败 (锁屏, 超时, 设备断开等) 不自动重试同一次复制, 下一次复制再尝试. 原因: 避免锁屏时反复启动辅助程序; 已提交的写入按现有契约不得重试.
- 模块内状态行: 未生效原因, 监听中, 推送中, 最近一次已推送 (时间), 最近一次未推送的原因. 原因: 无 toast 时这是唯一反馈.
- 切换设备, 设备断开或换连接方式后不向旧目标写入. 原因: 沿用现有剪贴板防串写契约.
- 中英文文案同步.

## 不做

- 手机 -> 电脑方向自动同步 (需要手机端常驻监听).
- 图片, 文件等非文本剪贴板内容.
- 同时推送到多台设备.
- 敏感内容识别 (密码管理器标记, 自定义排除规则, 推送前确认).
- Linux 支持.
- 设备栏等模块外的全局状态标记.

## 验收标准

- [x] 开关默认关闭; 关闭时不读取电脑剪贴板. 原生目标不变及 watcher 单测共同覆盖.
- [x] 模块开关与设置行状态同步; 重启应用后保持; 设置 > 通用 的分区重置和全局重置把它恢复为关闭.
- [x] 打开后, 在其他应用复制一段新文本, 不切回本应用, 手机剪贴板在 2 秒内变为该文本.
- [x] 本应用窗口最小化或被完全遮挡 5 分钟以上后, 复制新文本仍能推送到手机. 最小化超过 5 分钟及全屏 TextEdit 遮挡均通过.
- [x] 打开开关时剪贴板里已有的内容不会被推送.
- [x] 重复复制同一内容不会重复推送; 换一台设备后复制同一内容会推送到新设备.
- [x] 连续快速复制多段文本, 手机最终得到最后一段, 中间不排队推送每一段. 原生验证最终文本, 不排队策略由 watcher 单测覆盖.
- [x] 手机锁屏时推送失败不弹 toast, 模块内显示锁屏原因; 解锁后复制新内容可以推送.
- [x] 超过 256 KiB 或非文本内容不推送, 模块内显示原因, 手机剪贴板不变.
- [x] 切换或断开设备后停止向旧设备写入.
- [x] Linux 上开关和设置行禁用, 显示暂不支持. 使用既有自动化覆盖, 本轮未做 Linux 原生运行.
- [x] 手动 "推送到手机" / "复制到电脑" 行为不变.
