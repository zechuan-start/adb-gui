# 双语文档与截图实施计划

## 阶段 1: 脚本改造

1. `capture.mjs`: `OUTPUT_DIR` 按语言拼接; 新增 `--locale` 参数, 缺省两套都出.
2. 用 `addInitScript` 注入 `localStorage.locale`.
3. 复用同一 dev server 与浏览器实例循环两种语言.
4. 检查 `mock-tauri.js`, 确认返回的都是设备数据而非界面文案.

验证: `pnpm screenshots --locale en` 单独跑通; 输出目录正确.

## 阶段 2: 出图

5. 生成两套图到 `docs/images/en/` 与 `docs/images/zh-CN/`.
6. 逐张检查英文图无截断构图; 有截断则回到子任务 3 修对应组件, 不在截图里回避.
验证: 两套图各七张齐全; 同一份代码重跑两次结果一致.

## 阶段 3: README 与旧图清理

7. 两份 README 的图片路径改为各自语言目录.
8. 更新截图脚本说明的命令.
9. 各加一段语言设置说明.
10. 全仓搜索确认已无指向顶层旧路径的引用后, 删除旧 `docs/images/*.png`.

验证: 本地预览两份 README, 图片全部能加载, 语言与正文一致; 搜索 `docs/images/` 只剩两个语言目录的引用.

## 阶段 4: 收口

11. `index.html` 行为在开发说明里注明.
12. 记录 `validation.md`.

## 风险与回滚

| 风险 | 应对 |
| --- | --- |
| 图片路径大改导致外部直链失效 | 已确认接受. 删除旧图放在阶段 3 最后一步, 与 README 改动同一提交, 便于整体回滚 |
| 英文截图暴露布局截断 | 视为界面缺陷回到子任务 3 修, 不通过裁剪或改窗口尺寸掩盖 |
| 两套图的模拟数据不一致 | 模拟数据不随语言变化, 脚本里不做语言分支 |

图片与 README 改动可整体回滚, 不影响应用代码.
