# 设置面板结构与信息架构优化

## 产品与目标

`codex/settings-and-clipboard` 已交付统一设置存储和七个分组的全部偏好能力, 本任务只重构承载这些偏好的设置面板本身: 收敛分组分派与重置逻辑, 修正偏好存储归属造成的越界禁用, 补齐设置版本迁移路径, 并把七分组导航、行排版、说明文案和重置入口重排到与内容量匹配的形态.

不新增偏好项, 不改已有偏好语义与默认值, 不动 Rust 命令合约, 不改剪贴板链路.

## 已确认

- 2026-09-05 用户要求根据本分支提交内容优化设置面板, 先产出规划.
- 规划文档与实现都提交到 `codex/settings-and-clipboard`, 不新建分支, 不创建 PR.
- 2026-09-05 用户审阅可视化预览后确认两项决策并授权开始实现:
  - "性能"分组并入"通用", 分组数由七组减为六组. `performance` 偏好字段保持不变, 只是不再单独成组.
  - 不在界面上暴露 `theme` / `ui` 归属标签, 归属只体现为禁用行为差异, 必要时由错误横幅一句话说明.
- 按 `implement.md` 的阶段划分推进, 阶段一完成后交评审再决定阶段二.
- 不拆子任务: 三个阶段串行修改同一批文件(`SettingsDialog.tsx`, `lib/settings.ts`, `store/settings.ts`), 并行会重复冲突, 拆分收益低于协调成本.

## 代码基线

七分组面板与偏好存储的现状见下, 行号对应本分支 `495f097` 后的工作树.

- `src/components/settings/SettingsDialog.tsx` 469 行单文件承载分组定义、七组全部控件、Tab 焦点环、重置副作用和错误横幅. 分组分派是 if 链, `capture` 是末尾裸 `return`(`:80-292`, 兜底在 `:269`).
- `<fieldset disabled={!available}>`(`:441-446`) 覆盖整个内容区, 其中主题按钮属于 `useThemeStore`(`:83-110`), "显示日志的工作区"属于 `useUiStore`(`:224-245`), 两者都不存在于 `adb-gui-settings`.
- 重置逻辑分两处: `lib/settings.ts:306-319` 的 capture 特例, 与 `SettingsDialog.tsx:313-321` 的 theme/logOpen 特例.
- `lib/settings.ts:179-180` 对版本不匹配直接抛错, 无迁移函数, 错误态会禁用全部新偏好写入.
- 行原语有两套: `SettingRow`(min-h-12) 与 `Toggle`(min-h-11), 结构与语义不同, 都没有说明文字位置(`:34-70`).
- 分组内容量失衡: "性能"只有一个开关(`:249-258`), "应用"只有一行(`:266`), 而七个 tab 横向 wrap 占满一行(`:366-408`).
- "截图与录屏"里两个截图开关与一个录屏开关平铺无分隔(`:269-292`).
- "恢复全部默认"只在 `!available` 错误态出现(`:429-437`), 正常态没有全局重置.
- 页面快捷入口已统一走同一 `openSettings(section)`: `DeviceFileManager.tsx:668`, `CodeGeneratorPage.tsx:83`, `PerformancePanel.tsx:106`, `LogcatViewMenu.tsx:11`, `IndexRail.tsx:133`.
- `AppShell.tsx:49-68` 已在设置打开时屏蔽工作区热键, 但没有打开设置的热键.
- 前端测试基建是 `renderToStaticMarkup`(见 `ToolModule.test.tsx`), 无 jsdom, 现有 380 项测试没有一项覆盖设置面板.
- 窗口 `minWidth 900 / minHeight 600`(`src-tauri/tauri.conf.json:16-19`), 面板尺寸可按此下界设计, 无需移动端断点.

## P0 范围 · 结构与正确性

| 项 | 需求 | 价值 |
| --- | --- | --- |
| 分组注册表 | 分组顺序与标签改为声明式数据, 分派改为对 `SettingsSection` 的穷尽分支 | 消除隐式兜底; 新增分组漏写分支变成编译期错误, 不再静默渲染截图与录屏 |
| 分组合并 | "性能"并入"通用", 六个分组; `performance` 偏好字段与默认值不变 | 单开关分组不再单独占一个导航位; 性能页快捷入口改指向"通用" |
| 禁用归属 | 禁用范围按控件所属存储判定, 只有 `adb-gui-settings` 拥有的控件在 `!available` 时禁用 | 设置文件损坏时主题与日志工作区可见性仍可修改, 这两项数据本来完好 |
| 重置收敛 | 每个分组的重置目标(settings 字段集合 + 是否复位 theme/logOpen)由纯函数描述, 组件不再持有特例 | 重置规则可单测, 新分组只改一处 |
| 版本迁移 | `version < CURRENT` 走迁移链, 只有降级和迁移缺失才进错误态 | 下次 schema 升版不会让存量用户开机即错误态并被迫丢配置 |
| 分组拆文件 | 七组内容各自成文件, 弹窗只留壳 | 单文件 469 行降到可读规模, 顺带消除单行压缩写法造成的风格断层 |

## P2 范围 · 可选

- 打开设置的热键(macOS `⌘,` / 其他 `Ctrl+,`), 复用 `AppShell` 已有的屏蔽逻辑与统一入口.

## 共同要求

- 不新增偏好字段, 不改任何默认值, 不改 `adb-gui-settings` 的现有字段语义; 本任务不 bump `SETTINGS_VERSION`.
- 保持 theme 与 `adb-gui-ui` 各自的所有权边界, 不把它们的值搬进设置存储.
- 页面快捷控件与面板继续共用同一有效偏好和同一 `update` 动作, 不产生第二套写入路径.
- 保留现有 blueprint 视觉语言(`border-rule`、方角、hard shadow、`font-data`), 不引入组件库或新依赖.
- 保留写入失败与解析失败的现有反馈语义, 不静默回退, 不在未落盘时显示已保存.
- 未连接手机、无 Tauri 的浏览器预览下面板仍可打开与编辑, 原生目录能力继续按现状禁用而非伪造.
- 界面文案继续为简体中文, 本任务不引入 i18n.

## 不做

- 不把设置从 localStorage 迁到文件存储, 该议题独立评估.
- 不改 Rust 命令签名、DEX 协议、截图录屏保存与清理顺序.
- 不改分设备偏好、导入导出、跨机器同步等 phase-two 已列的 P1/P2 项.
