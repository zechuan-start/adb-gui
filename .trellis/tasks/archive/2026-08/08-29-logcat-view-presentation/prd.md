# 子任务 D: Logcat 视图呈现

> 父任务: `.trellis/tasks/08-29-logcat-refactor`
> 依赖: **子任务 A, B, C 均须先完成**. A 提供行结构与缓冲, B 提供列表与行组件, C 提供查询语言与 `crashKind` 判定结果.
> 这是重构的最后一个子任务, 完成后由父任务做集成评审.

## 目标

补齐 Android Studio Logcat 的呈现层能力: 长消息能读全, 显示字段可裁剪, 崩溃一眼可见, 并补上依赖 PID 正向映射的最后一块能力.

本任务也承担一个收尾价值: 建立 PID -> 进程名映射后, 子任务 C 记录的 "`pidof` 对多进程应用覆盖不全" 这个已知限制可以被真正解决.

## 范围边界

### 做

- **Soft-Wrap**: 长消息在列内换行显示, 默认关闭 (与 AS 一致), 由工具栏开关控制.
- **视图格式**: Standard / Compact 两档, 以及各字段的显示开关.
- **PID -> 进程名正向映射**: 新增后端 command, 前端缓存与失效策略.
- **包名列**: 可选显示, 数据来自正向映射.
- **`process:` 查询键**: 补齐 C 未做的键, 匹配完整进程名.
- **`package:` 实现升级**: 从 `pidof` 反向解析改为基于正向映射匹配, 解决多进程覆盖不全.
- **崩溃与堆栈高亮**: 消费 C 产出的 `crashKind`.

### 不做

- 不做 Up/Down the Stack Trace 导航 (父任务"不做范围", 待 `is:stacktrace` 稳定后再评估).
- 不做多标签页与分屏 (父任务"不做范围").
- 不做 Print / Screen Capture / Screen Record (项目已有独立的截图与录屏工具).
- 不做视图格式的持久化 (与查询历史收藏同属持久化决策, 父任务"不做范围"). 视图设置在会话内有效.
- 不改数据通道, 不改交互模型, 不改查询语法 (除新增 `process:`).

## 需求

### R1 Soft-Wrap

工具栏开关. 关闭时 (默认) 行为与现状一致: 固定行高, 长消息 ellipsis 截断. 开启时长消息在 message 列内换行, 完整可读, 行高随内容变化.

**必须保证**: 关闭状态下的性能与稳定性不因这个功能的引入而退化. 固定行高是快路径, 动态测量只在开启时生效.

### R2 视图格式与字段开关

- **Standard**: 显示完整字段 (日期可选, 时间, PID, TID 可选, 包名可选, tag, 等级, message).
- **Compact**: 减少字段, 让 message 成为焦点.
- 单独的字段开关允许用户自定义显示哪些列.

切换必须即时生效, 不需要重启日志流.

### R3 PID -> 进程名正向映射

新增后端 command 读取设备进程表, 建立 `PID -> 进程名` 映射. 前端缓存, 并有明确的失效策略. 映射只用于日志行入库时固化 `processName` / `packageName`; 后续快照不得回填或重解释历史行.

**失效要求**: 应用重启后 PID 会被复用, 陈旧映射会把日志归错应用. 因此未知或过期的 PID 在新入库行上必须固化为空, **绝不使用未来快照猜测历史行的归属**. 刷新失败可以保留上次快照用于诊断, 但不能延长其可用于新行归属的可信期.

### R4 包名列

可选显示的列, 内容为该行入库时固化的包名 (仅对可确认的 Android 应用进程名去掉 `:后缀`). 映射未知时显示空; 历史空值不使用最新 PID 快照回填.

### R5 `process:` 查询键

补齐 C 未实现的键, 匹配完整进程名 (含 `:remote` 之类的后缀). 支持 `~` 正则与 `=` 精确修饰符, 支持否定.

C 阶段对 `process:` 给出的"暂不支持"提示必须移除.

### R6 `package:` 升级

从 `pidof` 反向解析 (包名 -> PID) 改为匹配日志行入库时由正向映射固化的 `packageName`. 这解决 C 记录的多进程覆盖不全: `pidof com.example.app` 拿不到 `com.example.app:remote` 的 PID, 但正向映射能把同时存活的主进程与子进程固化为同一包名.

`package:mine` 语义不变 (当前前台应用).

**兼容要求**: 对映射已就绪后新产生且同时存活的日志, `package:` 必须覆盖主进程与 `:remote` 子进程. 映射建立前的历史未知行保持未知, 不以错误归属换取命中数量.

### R7 崩溃与堆栈高亮

消费 C 产出的 `crashKind`:
- `crash` 行: 明显的视觉强调, 在快速滚动中也能被扫到.
- `stacktrace` 行: 弱化的关联标记, 表明它属于某个崩溃块而非独立事件.

高亮必须在亮色与暗色模式下都成立, 且不能与等级配色冲突到难以辨认.

## 验收标准

### Soft-Wrap

- [ ] 默认关闭状态下, 行高, 列宽, 截断行为与子任务 C 结束时完全一致.
- [ ] 开启后长消息在 message 列内换行, 一条完整 Java 异常堆栈可在列表内读完, 无需导出.
- [ ] 开启状态下向上滚动浏览历史, 视口不出现明显跳动.
- [ ] 开启状态下高频日志持续流入且处于跟随底部时, 滚动稳定.
- [ ] 开启状态下 ring buffer 发生淘汰时, 处于 detached 的视口不出现明显漂移.
- [ ] 反复开关 soft-wrap 不导致滚动位置丢失或列表空白.
- [ ] 关闭 soft-wrap 后立即回到固定行高快路径 (可通过是否调用测量来验证).

### 视图格式

- [ ] Standard 与 Compact 切换即时生效, message 在 Compact 下明显更宽.
- [ ] 每个字段开关都能独立生效: 日期, 时间, PID, TID, 包名, tag, 等级.
- [ ] 关闭全部可选字段后 message 占满宽度且不错位.
- [ ] 切换视图格式不影响当前查询与滚动位置.
- [ ] 视图设置在切 tab 后保持 (会话内有效), app 重启后回到默认.

### PID 映射与包名列

- [ ] 包名列开启后, 应用日志行显示正确包名.
- [ ] 系统进程行显示其进程名或空, 不显示错误的应用包名.
- [ ] 强制停止应用后重启, 新 PID 的行显示正确的新包名, 不显示陈旧映射.
- [ ] 映射未知的 PID 显示为空, 而不是显示上一个占用该 PID 的进程名.
- [ ] 映射刷新失败时保留上次快照用于诊断, 但过期快照不再用于新行归属.
- [ ] 切换设备后映射完全重建, 不残留上一台设备的数据.
- [ ] PID 被复用后, 已入库历史行的进程名与包名不随新快照变化; 原本未知的历史行仍为空.

### `process:` 与 `package:`

- [ ] `process:<完整进程名>` 命中对应行, 含 `:remote` 后缀的进程可被单独定位.
- [ ] `process~:` 正则与 `process=:` 精确均生效, `-process:` 否定生效.
- [ ] C 阶段的 `process:` "暂不支持"提示已移除.
- [ ] 对一个多进程应用, `package:<包名>` 能同时匹配主进程与 `:remote` 子进程的日志 (这是相对 C 的改善, 需实际验证).
- [ ] `package:mine` 语义不变.
- [ ] 映射已就绪后新产生的日志没有覆盖回退; 映射建立前的历史未知行不做猜测性补齐.

### 崩溃高亮

- [ ] 制造一次真实崩溃, crash 行在快速滚动中可被扫到.
- [ ] stacktrace 行有弱化的关联标记, 与 crash 行可区分.
- [ ] 亮色与暗色模式下高亮均成立且可读.
- [ ] 高亮不与等级配色冲突 (E/F 级的红色与 crash 高亮并存时仍可辨认).
- [ ] 普通日志无任何高亮, 无误标.

### 回归

## 约束

继承父任务全局约束. 本任务特别相关的:

- **禁止**让 soft-wrap 默认开启. AS 默认关闭, 且动态测量是本任务最大的性能与稳定性风险源.
- **禁止**在 soft-wrap 关闭时走动态测量路径.
- **禁止**显示可能陈旧的包名. 宁可显示空.
- **禁止**用最新进程表重新解释历史日志行; 进程名与包名只在入库时固化一次.
- **禁止**让 `package:` 升级造成匹配范围缩小.
- 新增 command 必须返回 `Result<T, String>`, 走 `run_adb_with_serial` 或既有 device 命令 helper, 并注册进 `generate_handler!`.
- 设备端进程表读取不得把用户输入拼进 shell 命令.
- 高亮只用语义 token, 不硬编码颜色.
