# 子任务 A: Logcat 数据通道与会话重构

> 父任务: `.trellis/tasks/08-29-logcat-refactor`
> 依赖: 无. 这是 4 个子任务的地基, 必须最先完成.
> 后续子任务 B / C / D 全部建立在本任务产出的 store 与索引结构之上.

## 目标

把日志的**数据通道**从"每行一次 IPC + 每行一次 setState"换成"批量聚合 + 每帧一次更新", 并把日志状态从组件内搬进 store; 同时根治切换设备时杀错子进程的竞态, 让子进程异常退出变得可见.

本任务**不改交互形态, 不改视觉**. 用户能感知到的变化只有两个: 不卡了, 以及切设备不用切两次.

## 范围边界

### 做

- 后端: 批量 emit, per-serial 会话管理与 session_id 校验, stderr 摘要, 退出事件.
- 前端数据层: `lib/logcat.ts` (行结构, ring buffer, 过滤谓词), `store/logcat.ts`, `hooks/useLogcatStream.ts`, `lib/tauri.ts` 桥接更新.
- 现有 `src/components/Logcat.tsx` 的**最小改造**: 只把数据来源从组件内 `useState` 换成新 store 与新 hook, 保持组件仍是单文件, 保持工具栏与列表的现有结构和视觉不变.

### 不做

- **不拆分组件**, 不新建 `components/logcat/` 目录, 不改名 `LogcatViewer.tsx`. 全部属于子任务 B.
- **不改交互语义**: 暂停按钮仍是现状的三分支行为, 跟随逻辑仍是现状实现. 解耦属于子任务 B.
- **不引入查询语言**. 过滤仍是现状的四套控件与语义, 只降低执行成本. 属于子任务 C.
- **不做 soft-wrap, 不改行高, 不改列布局**. 属于子任务 D.
- 不做缓冲容量的用户可配置 UI.
- 不做设备上线自动重连 (本任务只让"已断开"可见, 手动 Restart 属于 B).

### 为什么要包含"组件最小改造"

如果本任务只改后端与新建数据层而不接现有组件, 结束时项目处于"后端已换协议, 前端还在听旧事件"的坏状态, 无法独立验证也无法独立归档. 因此最小改造是本任务可独立交付的必要组成部分. 代价是 `Logcat.tsx` 会短暂处于"用了新数据层但仍是 616 行单文件"的中间状态, 由子任务 B 收尾.

## 需求

### R1 后端批量聚合

reader 循环按"满 N 行或 T 毫秒"聚合后 emit 数组事件, 取代每行一次的 `logcat-line`. 低流量时单行日志的到达延迟不超过 T; 高流量时 emit 次数由行数上限主导.

### R2 per-serial 会话与 session_id 校验

后端按 serial 管理子进程, 每次启动分配全局单调递增的 session_id. `stop_logcat` 接收 `(serial, session_id)` 并且**只在两者都匹配时才 kill**. 前端对收到的批次校验 session_id, 不匹配的直接丢弃.

这是根治现状竞态的关键: 只按 serial 停止仍不安全, 因为 `A -> B -> A` 会复用同一个 serial, 迟到的 stop 依然可能杀掉同 serial 的新会话.

### R3 子进程退出可见

stderr 不再丢弃, 保留尾部摘要. 子进程退出 (EOF 或读取错误) 时 emit 退出事件并携带原因与摘要. 前端据此把流状态标为已断开.

本任务只要求"状态正确且可见" — 工具栏指示器不再于断开时显示为正常. 断开提示条与重连按钮属于子任务 B.

### R4 定容缓冲, 追加不复制

日志缓冲改为定容环形结构, 追加与淘汰均为 O(1) 且不复制窗口. 容量提到 10000.

### R5 过滤索引增量维护

过滤结果不物化成行数组, 只维护升序的 seq 索引. 追加一批日志时只对新行判定谓词; 过滤条件变更时才全量重建.

### R6 过滤热点降本

行入库时一次性计算供搜索比较使用的小写字段; 搜索输入做 debounce. 取代现状"每次过滤都对每行重新 `toLowerCase()`".

### R7 渲染频率与数据频率解耦

事件回调只写 ref 缓冲, 由 `requestAnimationFrame` 合并成每帧最多一次 store 更新.

### R8 日志状态进 store

新建 `useLogcatStore`, 承载缓冲, 索引, 过滤条件, 流控状态与会话身份. 组件不再持有日志数据.

本任务只要求状态搬迁到位; "切 tab 不丢现场"依赖 `App.tsx` 的挂载方式改造, 属于子任务 B.

## 验收标准

### 性能与手感 (真机)

- [ ] 触发高频日志 (启动大型 app), 日志页持续滚动期间搜索框输入不掉字, 无可感知卡顿.
- [ ] 切到日志页的首次加载 (`-T 5000` 初始 dump) 不出现整秒级冻结, 列表可立即滚动.
- [ ] 高频日志下 store 更新频率不超过每帧一次 (通过 store 更新计数断言或临时插桩验证).
- [ ] 低流量时 (偶发单行日志) 单行到达延迟不超过批量时间窗上限, 观感上仍是"实时".

### 设备切换与会话

- [ ] 连续快速切换两台在线设备 (A -> B -> A), 每次切换后日志都在 2 秒内出现, 不需要二次切换.
- [ ] 切换后列表中不含上一台设备的行.
- [ ] 旧会话的迟到批次不进入新列表 (可通过临时插桩统计被丢弃的批次数验证).
- [ ] 快速连续切换设备 5 次后, 后端不残留孤儿 logcat 进程 (用 `ps` 或任务管理器确认).

### 流中断

- [ ] 日志流进行中拔掉设备 (或 `adb kill-server`), 前端流状态在 2 秒内变为已断开, 工具栏指示器不再显示为正常.
- [ ] 断开时已有日志仍保留可查, 不被清空.
- [ ] 子进程无法启动时错误经 toast 可见, 不静默失败.
- [ ] 断开原因摘要 (stderr 尾部) 能在 UI 或 console 中取到, 不为空丢失.

### 数据结构正确性 (单测)

- [ ] ring buffer: 未满追加, 恰好满, 溢出淘汰, `bySeq` 命中与越界, `clear` 后复用, 容量边界 (1 和 capacity) 全部覆盖.
- [ ] 过滤索引: 增量追加, 头部淘汰后索引失效项被正确跳过, 过滤条件变更后全量重建, 索引压缩后逻辑长度不变.
- [ ] 过滤谓词: 等级阈值语义, 关键字命中 tag 与 message, tag 精确匹配, PID 集合过滤, 以及各条件叠加, 逐条与现状语义对齐.
- [ ] store: 会话校验丢弃错误批次, 暂停期间批次进积压区, 恢复后一次性补入, 切设备 reset 归零.

### 回归 (行为必须与现状完全一致)

- [ ] 等级按钮, 应用过滤下拉, 关键字搜索, tag 点击过滤及其 chip 清除, 四者行为与叠加效果不变.
- [ ] 暂停/恢复行为不变 (含现状的三分支语义, 本任务不改).
- [ ] 导出仍导出当前过滤结果的 `raw`, 文件名带时间戳, 完成后 reveal 并 toast 路径.
- [ ] 清屏行为不变 (本任务不拆分清屏与清设备缓冲, 属于子任务 B).
- [ ] 无设备时仍显示"请先连接设备以查看 Logcat".
- [ ] 分隔行 (`--------- beginning of main`) 仍以 level `I` 进入列表, 不被丢弃.
- [ ] `cargo test`, `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `corepack pnpm test`, `corepack pnpm build` 全部通过.

## 约束

继承父任务 prd 的全局约束. 本任务特别相关的:

- 子进程必须继续走 `adb::prepare_async_command`, 新增的 stderr pipe 不得绕过它.
- `parse_logcat_line` 的解析语义不得回退, 既有 6 个回归单测除去 `serial` 断言外逐条保留.
- 移除 `LogcatLine.serial` 时必须同步 Rust 结构体, TS interface 与单测, 三者不得只改其一.
- 新 command 必须注册进 `lib.rs` 的 `generate_handler!`.
- 禁止在事件回调里直接调用 store action, 必须经 ref 缓冲 + rAF 合并.
- 禁止先 `startLogcat` 再注册监听 (会丢初始 dump).
