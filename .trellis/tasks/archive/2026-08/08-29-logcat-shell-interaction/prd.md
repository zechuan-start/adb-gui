# 子任务 B: Logcat AS 式交互外壳

> 父任务: `.trellis/tasks/08-29-logcat-refactor`
> 依赖: **子任务 A (`08-29-logcat-stream-pipeline`) 必须先完成**. 本任务建立在 A 产出的 store 与索引结构之上, 且 A 结束时留下的"616 行单文件但已用新数据层"的中间状态由本任务收尾.
> 后续: 子任务 C 的查询框接入本任务拆出的工具栏; 子任务 D 的视图能力接入本任务拆出的列表与行组件.

## 目标

把日志页的**交互模型对齐 Android Studio Logcat**, 并把 616 行单文件组件拆成职责清晰的组件与 hook.

核心是一件事: **让"数据是否在流入"和"视口是否跟着底部跑"变成两个独立的、各自有专属控件的状态.**

## 需求澄清: 为什么这是重点

调研 (`../08-29-logcat-refactor/research/android-studio-logcat-model.md` 第 1 节) 确认了一个反直觉的事实:

AS 的滚动行为与本项目现状**其实是同一个行为** — 上滚只关闭自动滚动, 数据继续流入. 现状代码里数据也没停. 真正让人觉得"滚动时暂停不是好方案"的是**控件合并**: 现状只有一个暂停键, 且仅"未跟随"时它也显示为 Play 图标 (`paused || !following` 共用一个条件), 使用户误判数据已停; `handlePauseToggle` 需要三个分支才能表达两个正交状态的组合.

AS 是三个独立控件:

| 控件 | 职责 | 现状 |
|---|---|---|
| `Pause` | 真正暂停数据输出 | 与"停止跟随"共用一个按钮 |
| `Scroll to the End` | 只管视口, 恢复跟随并回到底部 | 无独立控件, 藏在暂停按钮的第二分支里 |
| `Restart` | 清空并重连 logcat | 完全没有 |

另外 AS 中**在日志区域点击任意位置也会停止跟随** (因为点击通常意味着要盯某一行), 且被点击的行会保持可见. 现状只监听滚轮与触摸.

## 需求

### R1 状态正交化

`streamMode` (`live` / `paused`) 与 `followMode` (`follow` / `detached`) 完全独立, 四种组合都有明确定义的行为, 见 design 的行为矩阵. 不再存在需要三分支才能表达的切换函数.

### R2 三个独立控件

- **Pause**: 只切换 `streamMode`. 暂停期间列表完全静止, 显示积压计数; 恢复时补入积压并回到底部.
- **Scroll to the End**: 只切换 `followMode` 为 `follow` 并滚到底部. 与数据流无关.
- **Restart**: 清空前端窗口并重连 logcat (新 session), 保留过滤条件.

三个控件的图标与 tooltip 必须让用户无需试探即可区分. 特别地, `Pause` 的图标**不得**因为 `followMode` 变化而改变.

### R3 视图内点击停止跟随与行锚定

在日志列表区域点击任意位置即切到 `detached`. 若点击落在某一行上, 该行被记为锚定行, 后续数据流入时该行保持在视口中的位置不跳动.

### R4 切 tab 不丢现场

日志页首次进入后挂载, 之后切走不卸载. 切回时日志内容, 过滤条件, 滚动位置, 暂停状态全部保持, 且切走期间新日志继续进入缓冲.

未进入过日志页时不挂载, 不启动 logcat 子进程.

### R5 断开可见且可恢复

`streamState === "disconnected"` 时在工具栏与列表之间出现提示条, 显示断开原因摘要, 并提供重连入口. 已有日志保留可查.

### R6 清屏与清设备缓冲分离

- **清屏**: 只清前端窗口, 单击直接生效, 不发任何 adb 命令.
- **清空设备日志缓冲区**: 独立入口, 视觉上与普通动作区分, 需二次确认才执行 `adb logcat -c`.

### R7 组件与 hook 拆分

`Logcat.tsx` 拆为容器 + 工具栏 + 列表 + 行四个组件, 跟随逻辑抽为 hook. 行组件 memo 化. 拆分后单个文件不超过约 200 行.

### R8 文件命名纠正

`LogcatViewer.tsx` (内容是 `QuickKeysTool`) 改名为 `QuickKeys.tsx`, `App.tsx` 的 import 同步更新.

## 验收标准

- [ ] `Pause` 期间列表完全静止, 工具栏显示暂停态与积压行数; 恢复后积压行一次性补入且视图回到底部.
- [ ] 向上滚动离开底部时**数据继续流入** (总行数继续增长), 出现未跟随提示与新增计数; `Pause` 按钮的图标**保持为暂停图标不变**.
- [ ] 暂停态与未跟随态在 UI 上可同时存在且可区分 (四种组合逐一验证).
- [ ] 点击 `Scroll to the End` 恢复跟随并回到底部, 不影响 `streamMode`.
- [ ] 在 `paused` 且 `detached` 的组合下, 点击 `Scroll to the End` 只恢复视口, 数据仍处于暂停.

- [ ] 在日志区域点击任意空白处, 跟随停止.

## 约束

继承父任务 prd 的全局约束. 本任务特别相关的:

- 禁止把"暂停"和"回到底部"塞回同一个按钮 (这是本任务存在的理由).
- 禁止用条件渲染承载日志页 (`{activeTab === "logcat" && ...}`).
- 禁止让"清屏"触发任何 adb 命令.
- 破坏性动作必须复用项目既有的内联二次确认模式 (`ActivityMonitor.tsx` / `PackageManager.tsx` 的 `confirmAction` 状态机), 不引入新的 dialog 组件.
- `<button>` 必带 `type="button"`; 条件 class 用 `cn()`; 颜色只用语义 token.
- 不扩大过滤语义 (留给子任务 C).
