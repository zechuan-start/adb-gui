# 二维码和条形码生成设计

## 产品形态

该功能是 ADB GUI 内独立的本地生码工作区, 与设备操作解耦. 它使用现有顶部页签导航, 不塞入“工具”页的小卡片网格, 不新增侧边栏, 也不依赖在线服务.

核心原则:

- 输入、生成配置和结果在同一屏完成, 适合粘贴批量数据后快速扫码.
- 草稿与最近一次生成结果分离, 用户明确触发生成, 避免大批量输入时反复重算.
- 大批量结果只在进入可见范围时生成码图, 不以一次性渲染换取实现简单.
- 编码数据不做隐式裁剪、去重或格式修复; 失败项显式报错, 不自动切换其他码类型.
- 码图始终使用白底黑码和稳定留白, 不跟随主题反色.

## 页面布局

应用默认窗口为 `1200x800`, 最小窗口为 `900x600`. 在项目支持范围内使用全高双栏工作区:

```text
┌────────────────────────────────────────────────────────────────────┐
│ 现有设备上下文栏                                                   │
├────────────────────────────────────────────────────────────────────┤
│ [工具] [日志] [应用] [生码]                                       │
├─────────────────────────┬──────────────────────────────────────────┤
│ 输入区 320px            │ 结果区 minmax(0, 1fr)                   │
│                         │                                          │
│ [二维码 | 条形码]       │ 结果 1,248 项      二维码                │
│ 分隔符 [换行       ▾]   │ ┌──────────┐ ┌──────────┐              │
│                         │ │ 可见项 1 │ │ 可见项 2 │              │
│ [多行输入...........]   │ └──────────┘ └──────────┘              │
│                         │        虚拟滚动, 按视口生成              │
│ 错误或状态              │                                          │
│ [清空]          [生成]  │                                          │
└─────────────────────────┴──────────────────────────────────────────┘
```

- `App.tsx` 增加 `code` 顶层页签, 标签为“生码”, 使用 Lucide `QrCode` 图标.
- 生码页从 `900px` 起使用 `grid-cols-[320px_minmax(0,1fr)]`; 最小 Tauri 窗口保持双栏, 浏览器窄视口退化为上下排列并为输入区保留至少 360px 高度.
- 输入区是页面分栏, 使用右边框区分, 不包装成浮动卡片.
- 结果卡片是重复项目, 可以使用不超过 8px 的边框圆角. 二维码每个虚拟行显示 2 项, 条形码每行 1 项.
- 输入区和结果区各自保持稳定尺寸, 结果加载、错误和长文本不得改变分栏宽度.

## 输入工作流

### 控件

- 码类型使用两项 segmented control: “二维码”“条形码”. 默认二维码.
- 分隔符使用 `<select>`: “换行”“逗号”“分号”“制表符”“自定义”.
- 选择“自定义”后显示单行输入框; 内容作为完整字面值, 不解析正则和转义序列.
- 主输入使用填满剩余高度的 `<textarea>`.
- 底部提供清空图标按钮和主“生成”按钮. `Ctrl+Enter` 与生成按钮行为相同.

### 草稿和快照

输入区维护草稿 `draft`, 结果区只读取最近一次 `generatedBatch`:

```ts
type CodeType = "qr" | "code128";
type SeparatorMode = "newline" | "comma" | "semicolon" | "tab" | "custom";

interface GeneratorDraft {
  codeType: CodeType;
  separatorMode: SeparatorMode;
  customSeparator: string;
  input: string;
}

interface GeneratedBatch {
  id: number;
  codeType: CodeType;
  sourceRevision: number;
  values: string[];
}
```

- store 维护单调递增的 `draftRevision`; 任意草稿 setter 都递增版本, 生成快照记录当前版本. 这避免为了脏状态判断而复制整份原始输入.
- 草稿版本与结果 `sourceRevision` 不同时保留旧结果并显示“输入已修改”状态, 防止用户误认为旧结果来自当前输入.
- “生成”先校验分隔符, 再创建不可变结果快照并将虚拟列表滚动到顶部.
- “清空”显式清除草稿、错误和结果.
- 使用无持久化中间件的 `useCodeGeneratorStore`, 使页签卸载后会话数据仍在内存中, 应用重启后自然清空.

## 解析契约

共享纯函数放在 `src/lib/codeGenerator.ts`:

- `newline`: 使用 `\r\n|\n|\r` 分割, 正确移除平台换行符.
- `comma`: 字面量 `,`.
- `semicolon`: 字面量 `;`.
- `tab`: 字面量 `\t`.
- `custom`: 使用完整非空字符串执行字面量分割.
- 仅过滤 `value.length === 0`; 不调用 `trim()`, 纯空格项目也作为真实数据编码.
- 保留原始顺序和重复项.
- 自定义分隔符为空时返回具名校验错误, 不回退到换行.

## 码图生成

### 依赖和边界

- 二维码使用 `qrcode` 的浏览器 Canvas API.
- 条形码使用 `jsbarcode`, 固定 `format: "CODE128"`.
- `qrcode` 增加 `@types/qrcode`; `jsbarcode` 自带类型声明.
- 不使用 React 包装库或手写编码算法. 两种库都在函数组件 `useEffect` 内通过 `canvas` ref 调用, 允许捕获单项错误并清理过期结果.

### 视觉和错误

- 二维码使用白色背景、黑色前景和规范静区, 列表尺寸约 176px, 放大预览约 360px.
- 条形码使用白色背景、黑色线条、Code 128 和可读文本; 列表高度固定, 超宽内容在白色画布区域内横向滚动.
- 每个码组件保留稳定占位尺寸. 生成中使用轻量加载态, 成功后显示 Canvas, 失败后在相同区域显示错误文本.
- 异常只写入当前结果项, 其余项继续渲染. 不吞错, 不自动改用二维码或其他条形码制式.

## 虚拟滚动和懒生成

复用项目已有 `@tanstack/react-virtual`:

- 二维码按 2 项组成一个固定高度虚拟行; 条形码按 1 项组成一行.
- `count` 使用虚拟行数, `overscan` 只保留少量相邻行, `useFlushSync: false` 以适配 React 19.
- 只有 `virtualizer.getVirtualItems()` 返回的行进入 React 树; Canvas 组件挂载时生成, 卸载时释放.
- 列表使用结果索引和生成快照版本形成稳定 key, 重复值不能共用 key.
- 生成新快照时重新测量并回到顶部; 容器尺寸变化时重新测量现有虚拟行.
- 不设置常规批量条数硬上限. 全量工作仅限字符串分割和 `values` 数组, 昂贵的码图计算受视口范围限制.

## 放大预览

- 点击任意结果卡打开原生 `<dialog>` 模态预览; 无法编码的项目在放大区域显示相同错误, 保持索引导航连续.
- 对话框显示当前位置 `n / total`、完整原始内容和放大码图.
- 使用 Lucide `ChevronLeft`、`ChevronRight` 和 `X` 图标按钮; 按钮有 tooltip 和可访问名称.
- `ArrowLeft` 切换上一项, `ArrowRight` 切换下一项, 到达首尾后保持当前位置且对应按钮禁用, 不循环.
- `Escape` 关闭对话框. 键盘监听只在对话框打开时生效, 不劫持输入区方向键.
- 原生 dialog 负责模态焦点范围;关闭后恢复到触发结果. 页签切换会关闭预览, 但 store 中草稿和结果保持.

## 状态与反馈

| 状态 | 页面行为 |
|---|---|
| 初始 | 输入区可编辑, 结果区显示短空状态“暂无结果” |
| 草稿已改 | 旧结果保留, 结果标题显示“输入已修改” |
| 空输入 | 生成按钮触发后在输入区显示行内错误 |
| 自定义分隔符为空 | 自定义输入框下显示行内错误, 不生成 |
| 有效批量 | 显示生成类型、结果总数和虚拟列表 |
| 单项失败 | 对应卡片显示具体错误, 其他卡片不受影响 |

本功能全部在前端本地执行, 不使用全局成功 Toast. 输入校验和单项编码错误贴近控件或结果展示.

## 兼容性和回滚

- 只修改前端依赖、顶层导航和新增前端模块, 不修改 Rust/Tauri 命令协议.
- Canvas 在 Tauri WebView 和现代浏览器中可用;亮色和暗色主题下强制白底黑码.
- 回滚时删除生码页、store、解析 helper 和两个生成依赖, 并从 `App.tsx` 移除页签即可, 不涉及数据迁移.

## 实现约束

- 不用 `dangerouslySetInnerHTML`, 不手工拼接 SVG.
- 不使用 class 组件, `any`, 非空断言或直接 DOM 查询; Canvas 和 dialog 通过 React ref 管理.
- 不把草稿和结果存入 `localStorage`.
- 不为失败数据建立静默 fallback 或第二套编码逻辑.
